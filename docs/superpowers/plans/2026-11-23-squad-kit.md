# Squad Kit (piece 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A session's role carries its instructions, its permission fence and its model; a project's squad starts
with one command; the dangerous-commands hook stops blocking message text; cards waiting on a person stop being pinged.

**Architecture:** Role texts are markdown in `prompts/roles/`, loaded into `cb.role_texts` by `db/setup.ts` after the
schema, served by `cb role`. Permission files are static JSON in `kit/permissions/`. The squad file is a validated
`squad` jsonb on `cb.projects` (SQL), and `cb squad up` is a new CLI module that plans with a pure function and acts
through herdr. The hook is a node script in `kit/hooks/`, tested with `node --test`.

**Tech Stack:** Node 24 running `.ts`/`.mjs` directly, Postgres (`postgres` package), herdr CLI 0.9.x, Claude Code
`--settings` / `--permission-mode`. Tests: `node --test` against the test Postgres at 127.0.0.1:5434.

**Spec:** `docs/superpowers/specs/2026-11-23-squad-kit-design.md` (approved, Q2363), on top of
`docs/superpowers/specs/2026-11-22-squad-design.md`. Card #3599.

## Global Constraints

- Rules live in SQL `cb.*` functions; CLI stays thin except `cb squad up` (it drives herdr, which the board can't).
- Schema is idempotent: `add column if not exists`; every new function has a `drop function if exists cb.<name>
  cascade;` line in a new section at the end of `db/schema.sql` titled `-- Squad kit (#3599)`; `#variable_conflict
  use_variable` in every plpgsql body with unprefixed params.
- Every `case` in `cli/cb.ts` needs an entry in `cli/help.ts` GROUPS (`test/help.test.ts` enforces it).
- Roles, exactly: `lead`, `architect`, `owner`, `builder`, `reviewer`, `qa`, `investigator`.
- Models, exactly: `opus`, `sonnet`, `haiku`, `fable`. Defaults: opus for lead, architect, owner, reviewer,
  investigator; sonnet for builder and qa.
- Mac cap: **8** live sessions on the `macbook` machine, all projects counted.
- Every squad session starts with `--permission-mode bypassPermissions --model <m> --settings <board
  checkout>/kit/permissions/<role>.json` (Q2362). Deny rules are the only fence.
- Session names: `<project>-<L><n>@<machine>` with L = `A` architect, `B` builder, `R` reviewer, `Q` qa,
  `I` investigator; owners `<project>-O-<area>@<machine>`; the lead `orch@<machine>`.
- Board text and role texts carry no identifiers, patient data or provider names; plain words.
- Board repo rules (`CLAUDE.md`): worktree branch only; never touch `F:/Work/claude-board` or the live board DB; test DB
  `claude_board_test_kit`; take `cb lock take db2` for test runs; `NODE_OPTIONS=--max-old-space-size=4096` and a
  timeout on every run; merge only with Ahmed's go.
- The global hook (`~/.claude/hooks`, `~/.claude/settings.json`) is changed only in Task 7, only after Ahmed says yes
  in the terminal.

**One test command** (replace the file), from `C:/w/kit`:
`CB_TEST_DB=claude_board_test_kit NODE_OPTIONS=--max-old-space-size=4096 timeout 600 node --test --test-concurrency=1 test/<file>.test.ts`

## Review Focus

1. **`cb squad up` run twice, or while a session is compacting:** no second pane for a live name (board seen < 90 s,
   or a herdr agent of that name on that machine). Test in Task 4.
2. **A role file edited or removed in `prompts/roles/`:** the next `db/setup.ts` run updates the board copy, and a
   removed file's row is deleted. Test in Task 1.
3. **A dangerous command hidden in a compound or remote command** (`cd x && git reset --hard`, `ssh vps1 "sudo
   reboot"`, `psql -c "drop table t"`) still blocks, while the same words in `cb tell` / commit messages pass. Test in
   Task 6.
4. **A squad file that would put more than 8 sessions on the Mac**, alone or with other projects' live sessions:
   `squad set` refuses the first, `squad up` stops before the cap on the second. Tests in Tasks 3 and 4.
5. **Test wipes:** `freshDb()` truncates every `cb` table; `cb.role_texts` must survive it (it is loaded once per
   process by setup). Test in Task 1.

  ```json
  {"machines": {"macbook": {"herdr": "macbook", "repo": "/Users/<you>/Work/x", "board": "/Users/<you>/Work/claude-board"},
                "shaltoot": {"herdr": null, "repo": "F:/Work/x", "board": "F:/Work/claude-board"}},

             "owner": {"model": "opus", "machine": "macbook"}},
   "areas": ["claims", "preauth"]}
  ```
  `herdr` null = this PC (no `--machine`). `model` optional (default from Global Constraints). `owner` has no
  `count`: one owner per area.

  known model; `machine` is a key of `machines`; each machine has `repo` and `board`; areas are slugs

  (`only Ahmed or the lead sets the squad`). Logs an event (kind `updated`: `edited` is not an allowed event kind; summary `squad updated`). Absolute `repo`/`board` only, a
  `herdr` key on every machine, slug machine keys; the Mac cap counts by herdr label `macbook`.
- CLI: `cb squad set <project> -f <file|->`, `cb squad show <project> [--json]`; show prints one line per role:

### Task 4: `cb squad up`

**Files:**
- Create: `cli/squad-up.ts` (plan + run), Modify: `cli/cb.ts` (`squad up`), `cli/help.ts`
- Test: `test/squad-up.test.ts` (new, no herdr calls)

**Interfaces:**
- Consumes: `cb.squad_get` (Task 3), `cb.sessions_overview` (live sessions), Task 2 file paths.
- Produces: `planSquad(project: string, squad: Squad, live: {actor: string, machine: string}[], herdrAgents:
  Record<string, string[]>) : {start: Launch[], skip: string[], refused: string[]}` where `Launch = {name, role,
  area?, model, machine, herdr: string | null, cwd, settings, prompt}`; `settings` = `<board>/kit/permissions/<role>.json`;
  `prompt` = `cb iam <name> <project> --role <role> [--area <a>] --model <model>, then cb role <role>, then cb next`.
- `cb squad up <project> [--dry-run]`: reads the squad, gets live sessions from the board and `herdr [--machine m]
  agent list` per machine, calls `planSquad`, prints `start <name> (<role>, <model>) on <machine>` / `skip <name>:
  live` / `refused <name>: the Mac already has 8 live sessions`; without `--dry-run` it then, per launch: finds or
  makes a tab with fewer than two panes (`herdr [--machine m] tab create` / `pane split --cwd <cwd>`), `herdr
  [--machine m] agent start <name> --kind claude --pane <p> --timeout 120000 -- --model <model>
  --permission-mode bypassPermissions --settings <settings>`, then `herdr agent prompt <name> "<prompt>"`. Check every
  herdr flag against `herdr <cmd> --help` before writing. A failed launch prints the error and continues with the next.
  Paths are passed as the squad file gives them; whether `~` is expanded in the remote pane is confirmed in the Task 8
  live check (if not, the squad file must hold absolute paths, and `squad set` should refuse `~`).

### Task 6: The dangerous-commands hook (Q2318)

**Files:**
- Create: `kit/hooks/block-dangerous.mjs`
- Test: `test/dangerous.test.ts` (new, spawns the script like `test/hook.test.ts`)

**Interfaces:**
- Produces: a PreToolUse hook: reads `{tool_input: {command}}` on stdin, prints `{"decision":"block","reason":"Blocked
  dangerous command: <pattern name>"}` or `{}`; exports `check(command): string | null` for tests.

Algorithm (the only part the tests don't fully pin):
1. Remove **message text**: the quoted text arguments of `cb tell|ask|log|add|done|move|fail|pass|edit`, `git commit
   -m|--message`, `gh pr create|comment|review --body|-b|--title|-t`; heredoc bodies whose command is `cb ...`, `cat >
   <file>` / `cat >> <file>`, or `git commit -F -`. Nothing else is removed.
2. Shell patterns match anywhere in what is left (fail closed; multi-word ones stay inside one command segment).
   Shell patterns (from today's hook): `rm -rf /`, `rm -rf
   /*`, `rm -rf ~`, `mkfs.`, `dd if=... of=/dev/`, the fork bomb, `chmod -R 777 /`, `mv ... /dev/null`, `wget|curl ...
   | sh`, power-off (`shutdown`), `reboot`, `init 0`, `init 6`, `> /dev/sda`, `format c:`, `del /f /s /q c:`,
   `--no-preserve-root`, `git push ... --force ... main|master`, `git reset --hard`.
3. SQL patterns (`drop database`, `drop table`, case-insensitive) match anywhere in what is left after step 1.

- [ ] **Step 1: Write the failing tests** with two lists:
  - must block: `git reset --hard`, `cd x && git reset --hard HEAD~1`, `sudo reboot`, `ssh vps1 "sudo reboot"`,
    `bash -c "rm -rf /"`, `psql -c "drop table t"`, `psql <<SQL\ndrop database x;\nSQL`, `curl https://x | sh`,
    `git push origin main --force`, `echo ok; shutdown -h now`, `node -e "require('child_process').execSync('reboot')"`,
    `grep -n reboot docs/ops.md`, `git log --grep shutdown`.
  - must pass: `cb tell orch "the shutdown is planned for 3am"`, `cb log 12 "do not run git reset --hard here"`,
    `git commit -m "doc: never reboot the VPS"`, `cat > notes.md <<'EOF'\nwe dropped the drop table idea\nEOF`,
    `gh pr comment 5 --body "avoid git reset --hard"`, `ls`, `pnpm test`.
  Note: `grep -n reboot` and `git log --grep shutdown` BLOCK: patterns match anywhere (controller ruling, fail closed);
  the words are fine in files. Power-off words are spared only inside file names (`graceful-shutdown.ts`).
- [ ] **Step 2: Run, expect FAIL**
- [ ] **Step 3: Implement `kit/hooks/block-dangerous.mjs`**
- [ ] **Step 4: Run `test/dangerous.test.ts`, `test/hook.test.ts`, expect PASS**
- [ ] **Step 5: Commit** `feat(squad): dangerous-commands hook that ignores message text (#3599)`
