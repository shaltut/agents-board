## The 12 members

1. `kind` = `opencode`. 2. `relayStart` = `pane-prestart`: the endpoint file (port, password) must exist before the agent starts, so the relay is up first.
3. `buildLaunch`: `--kind opencode -- <cwd> --hostname 127.0.0.1 --port <p> -m <provider/model> --auto`. Env: the caller's env minus `GITHUB_PERSONAL_ACCESS_TOKEN` and `CLAUDE_CODE_*`, plus `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` and `OPENCODE_DISABLE_AUTOUPDATE=1`. A given model must match the spec regex (`provider/model`); no model is allowed (no `-m`: OpenCode takes its config default, `freellmapi/auto`). The cwd must be absolute and is passed normalised (never a flag). Throws on: a bad model, a relative or empty cwd, a missing or out-of-range `CB_OPENCODE_PORT`, a missing `OPENCODE_SERVER_PASSWORD` (a seat nobody can reach is not started). No `--agent`: no per-role OpenCode agents exist yet (open).
   **The freellm wrapper is not in this path.** `herdr agent start --kind opencode` executes `opencode` directly, so the local freellm wrapper (folder guard) cannot be invoked from `LaunchSpec`. Instead `freellmRefusal(cwd, rule)` mirrors the wrapper and fails closed: the cwd is resolved to an absolute normalised path (`..`, `\\?\`, `/f/work/...` forms; empty, relative or unresolvable refuses), and the rule (under the protected folder only the allowed folders, case-insensitive; read from `~/.claude-board/freellm-rule.json` on each machine, a missing or malformed file refuses) is applied to the cwd AND to `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` (fixed argv), so a worktree outside the protected folder of a protected repo is refused. A git error inside a repo refuses (the wrapper itself ignores a git error; this copy is stricter); only "not a git repository" passes on the cwd alone. The root and allowed list are parameters (tests use a temp root, a real repo and worktree). It applies when the model starts with `freellmapi/` or no model is given. It is a copy of the wrapper's rule, not the wrapper: if the wrapper changes, the copy must too. **Owner decision recorded:** other providers (`anthropic/...` etc., addable in opencode.jsonc) are NOT checked; their own data terms apply.
   `FREELLMAPI_URL` and `FREELLMAPI_API_KEY` come from the pane's own env (the wrapper sets the URL and takes the key from env); they are never copied into a `LaunchSpec`, which is logged and visible.
4. `deliver` (expected, not live-checked): v1 `GET /session` (newest root session by `time.updated`; sessions with a `parentID`, i.e. subagent children, are skipped), then `POST /session/<id>/prompt_async` body `{parts:[{type:'text',text}]}`, Basic auth (`opencode:<password>`, username validated `[A-Za-z0-9._-]+`), 5 s timeout, `redirect: 'error'` (the Authorization header never follows a redirect), loopback only, port and password from `cb-seat-<seatKey>.opencode.json` (0600, atomic write, same shape as Claude's endpoint file). The spec's v2 `POST /api/session/{id}/prompt` exists in the binary but its body is unknown; v1 was chosen because its body is documented and stable.
5. `isAlive`: `GET /global/health`. Alive only on an HTTP answer from our server (200, or a 5xx) or a timeout. Dead: no endpoint file, 401/403/404 (another process on the port, or not our credential), and every other network error (ECONNREFUSED, ENOTFOUND, EHOSTUNREACH, ECONNRESET, EADDRNOTAVAIL, ...). Unlike Claude (which probes a socket on POSIX), the only "unknown counts alive" case is the timeout.
6. `readStatus`: herdr's `agent_status` (herdr's OpenCode plugin v13 already reports it: `~/.config/opencode/plugins/herdr-agent-state.js`); `safeToClose` = idle or done.
7. `close`: `herdr agent prompt <herdrName> /exit` through the Runner (TUI slash command), 30 s. Not live-checked, and it relies on the caller never closing a `working` seat (`supervise.ts` re-checks `safeToClose` first); `/exit` mid-turn is not safe.
8. `detectQuotaStop`: pane-tail regexes. Quota: `FreeUsageLimitError`, `insufficient_quota`, `usage|free limit reached|exceeded`, `quota exceeded|exhausted`, `out of credits`. Rate limit: `rate limit`, `429`, `too many requests`, `retrying in N`. `retryAfterSec` parsed from "retry/try again in|after N s|min". Only the last 8 non-empty lines are read, and a bare `429` or `rate limit` does not match (it needs error wording: `rate limited|reached|exceeded`, `HTTP/status/error 429`, `Too Many Requests`). Patterns are from the spec and OpenCode's error names, not captured pane text.
9. `guardInstallSpec`: `~/.config/opencode/plugins/cb-guard.js`, shim `kit/guard/shim-opencode.mjs`, matcher list `bash|powershell|edit|write|patch|apply_patch|multiedit|question` on all platforms.
10. `instructionMapping`: native `AGENTS.md`, project `CLAUDE.md` (fallback only), `~/.config/opencode/AGENTS.md`; env `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` (what the wrapper sets). No extra args.
11. `trustSpec`: no trust dialog expected; `--auto` answers permission prompts; no preseed path.
12. `disableAskSpec`: tool `question`, mechanism `permission`, target `opencode.jsonc permission.question = "deny"` (the guard also maps `question` to `ask`).

## Guard shim

stdin `{"tool","args","sessionID"}`; env `CB_ROLE`, `CB_PROTECTED_BRANCHES`, `CB_ALLOW_ASK`. Output: `{}` allow, `{"decision":"block","reason":...}` block, always exit 0 (same bytes as shim-claude; the plugin throws `Error(reason)`). Mapping: `bash|powershell` -> shell (needs string `args.command`), `edit|write|patch|apply_patch|multiedit` -> edit, `question` -> ask. Anything else blocks, including read-only tools and MCP names, so the plugin must forward only those tools. Fails closed like shim-claude (bad input, unknown tool or role, core load error).

## Integration (outside my files)

- `cli/squad-up.ts`: before `herdr agent start`, pick a free loopback port and a random password, call `writeOpencodeEndpoint(machine, pane, ...)`, and pass `CB_OPENCODE_PORT` and `OPENCODE_SERVER_PASSWORD` in `Launch.env`. Today nothing supplies them, so `buildLaunch` throws by design. Also set `CB_ROLE`/`CB_AGENT` (already done). Pane-prestart ordering (relay before agent) for this kind.
- Launch env: the pane's shell must already carry `FREELLMAPI_URL` and `FREELLMAPI_API_KEY` for a `freellmapi/*` model; the adapter never sets or copies them.
- Windows: the endpoint file's `0600` is ignored, so any process of the same user can read the password (the same class as Claude's token file); tighten the ACL in `writeOpencodeEndpoint` if that matters.
- **No OpenCode seat may be primary** until `install.mjs` writes the guard plugin AND a live test shows a blocked `git push` throws inside OpenCode. Today `buildLaunch` passes `--auto` and no guard plugin exists: the seat has no guard. This is safe now only because `cb.squad_set` refuses non-Claude primary seats; state this dependency in the PR.
- `cli/relay.ts`: nothing new if it keeps using `adapter.isAlive/deliver`; on exit call `clearOpencodeEndpoint`.
- `kit/guard/install.mjs`: learn to write `~/.config/opencode/plugins/cb-guard.js` (a plugin, not a settings entry). Its `tool.execute.before` must spawn `node shim-opencode.mjs` with `{tool,args,sessionID}` and `CB_*` env, throw `Error(reason)` on a block, and throw on any non-zero exit, timeout, or unparsable output. It must not touch the owner's other plugins in that folder. The plugin source is not in this change.
- `db/schema.sql`: `cb._check_model` already has the opencode regex per the spec; the primary-agent gate stays. `defaultModelFor('opencode', ...)` stays `null` on purpose, to match `cb._role_model` (a squad file must name `provider/model`, e.g. `freellmapi/auto`).
